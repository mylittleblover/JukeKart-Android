# MKW サウンドトラックパック（`.mkwpack`）、フォーマットバージョン 1

[简体中文](PACK-FORMAT.zh-Hans.md) | [繁體中文](PACK-FORMAT.zh-Hant.md) | [English](PACK-FORMAT.md) | **日本語**

このドキュメントはプロトコルそのものです。第 2 の実装者が本リポジトリの Kotlin コードを読まずにパックライターやパックリーダーを実装でき、後のメンテナーがそのルールの防御対象を見失ったまま安易に「簡略化」してしまわないように書かれています。

ステータス：`formatVersion` 1。リーダーとデータモデルは
`app/src/main/kotlin/com/mylittleblover/mkwplayer/pack/` にあります。

---

## 0. このフォーマットが存在する理由

『マリオカート ワールド』のコーステーマは単一のファイルではありません。ゲームが再生中に切り替える複数のパート——短いプレリュード、フルプレリュード、ブリッジ、メインループ、そして 1 つ以上のアウトロ——で構成されています。`BGM_Stage_Coaster` の実測データは次の通りです：

| part | frames | length | loop |
|---|---:|---:|---|
| Pre_Short | 534,857 | 11.143 s | 205714..534857 |
| Pre | 2,427,426 | 50.571 s | 452571..2427426 |
| Bridge | 88,320 | 1.840 s | none |
| Main | 3,373,711 | 70.286 s | 493714..3373711 |
| Outro00 | 226,286 | 4.714 s | none |

したがって 1 コースあたり 5〜8 個のアセットが存在します。30 コースで約 200 ファイルとなり、ジュークボックスのカタログを含めるとさらに数百ファイルが加わります。これらをユーザーに 1 ファイルずつ手動選択させるのは機能ではなく欠陥です——音を 1 つ聴く前に、数百ものファイルを正しい組み合わせで選ばなければならなくなるためです。

パックはこれを 1 回のインポートに置き換えます。単一ファイルで、すべての音声アセット、コース構造、ミュージックグラフ設定、マーカー/cue データ、ルートデータ、アートワーク、チェックサムを運びます。

そのため、このプロトコルは通常の音楽フォーマットが答える必要のない問いに答えなければなりません：
**何が既知の事実で、何が単なる選択であり、何が検証不能なのかを、ランタイムが勝手に「改善」できない形でファイルにどう記述するか？**

## 1. コンテナ

### 1.1 ZIP64 とその理由

`.mkwpack` は **ZIP64** アーカイブです。ZIP32 でも、独自ストリーム形式でも、tarball でもありません。

ZIP32 はサイズとオフセットを 32 ビットフィールドに格納するため、ロスレスのサウンドトラックパックは収まりません：

- 30 コーステーマ × 各 5 パート、平均 60 秒・48 kHz 16-bit ステレオとすると約
  1.7 GB（`48000 × 2 ch × 2 B = 192,000 B/s`、1 分あたり約 11.5 MB）。
- 実測カタログのジュークボックス楽曲群は 227 トラックあります。控えめに 1 曲 3 分としても、これだけで約 7.8 GB になります。
- カットシーン、シーケンス、バトルテーマ、アートワーク、チェックサムインデックスがさらに加わります。

フルパックは通常 10 GB を超えるため、32 ビットアーカイブではアドレス指定すらできません。ZIP64 はサイズとオフセットの双方を 64 ビットに拡張します。また ZIP64 は 65,535 エントリの上限も撤廃するため、アセットごとに 1 エントリ、さらにグラフ・マーカーセット・ルート・アートワークレコードごとに 1 エントリを格納するパックにとって重要です。

ZIP64 はインポート経路が必要とするもの——セントラルディレクトリ（central directory）も備えています。リーダーは何も復号・デコードすることなく全メンバーを一覧・検証でき、1 メンバーずつストリーミング読み込みできます。単一の連結ストリームでは、最初のアセットを検査するだけでも全体を読み通す必要が生じてしまいます。

### 1.2 他のすべてを読む前にリーダーが強制すべきルール

1. **`manifest.json` がアーカイブのルートに厳密にその名前で存在し、かつ先頭エントリであるべき（SHOULD）**。これにより 10 GB の音声に触れる前に使用不能なパックを拒否できます。
2. メンバー名は厳しく制限されます。次のいずれかに該当する名前のメンバーは、リーダーが必ず（MUST）拒否しなければなりません：
   - 絶対パスである、またはドライブ文字を含む；
   - パスセグメントとして `..` を含む；
   - バックスラッシュを含む；
   - セクション 2 のいずれのディレクトリ配下でもない；
   - パス区切り文字が 2 つ以上ある（レイアウトは厳密に 1 階層のみ）。

   これは机上の空論ではありません：そうでなければ `../../files/library.json` という名前の ZIP メンバーがステージングディレクトリ外へ書き込まれてしまいます。セクション 2 のディレクトリ検査が防御のすべてであり、省略不可です。
3. 暗号化は使用しません。暗号化されたエントリに遭遇したリーダーはそのパックを拒否します。
4. 音声エントリは `STORE`（メソッド 0）で格納します：圧縮済み音声はそれ以上圧縮されず、無圧縮格納されたエントリは展開せずに宣言サイズと照合できます。テキストエントリ（`manifest.json`、`catalog.json`、グラフ、マーカー、ルート）は `DEFLATE` 圧縮して構いません。アートワークはどちらでも構いません。リーダーは両方式に対応する必要があります。
5. `.mkwpack` 拡張子は自己申告に過ぎず、セキュリティ境界ではありません。リーダーは拡張子やプラットフォームが報告する MIME タイプではなく、`manifest.json` によってパックを識別します。

### 1.3 メディアタイプ

ファイルのメディアタイプは `application/zip` です。クライアント側のディスク上では `<packId>-v<packVersion>.mkwpack` と命名されますが、ファイル名は参考情報に過ぎません：真のアイデンティティはマニフェスト内にあります。

## 2. ディレクトリレイアウト

```
manifest.json                   必須、ルート直下、先頭エントリ
checksums.json                  必須、非アセットメンバーの整合性インデックス
catalog.json                    必須、パック自身が持つ収録トラックのカタログ
audio/<sha256>                  アセットごとに 1 エントリ；拡張子なし、サブディレクトリなし
music-graphs/<trackSlug>.json   コンパイル済みグラフを持つトラックごとに 1 つ（任意）
markers/<stageCode>.json        コースごとの cue/marker データ（任意）
routes/<routeId>.json           ルートプリセット（任意）
artwork/<sha256>.<ext>          画像、コンテンツアドレス指定（任意）
```

ルート直下にこれ以外のファイルが存在してはなりません。これらのディレクトリ外にあるメンバーは無害であっても拒否されます——「未知の余分なファイル」こそ、誰も検証しないペイロードをパックが運び始める入口だからです。

`music-graphs/` 内のメンバー名は宣言ではなく導出されます：トラックキーの `:` を `_` に置換します。例えばトラックキー `course:1111...`（32 桁の 16 進数）は
`music-graphs/course_1111....json` になります。名前を導出することで、マニフェストのどのフィールドもパスを持たずに済み、マニフェストがアーカイブ外を指すことができなくなります。

`markers/<stageCode>.json` と `routes/<routeId>.json` も同じルールに従います：コースコードまたはルート ID は `[A-Za-z0-9_-]{1,64}` に一致する必要があり、そのままファイル名として使われます。

### 2.1 `audio/` はコンテンツアドレス指定

エントリ名**そのもの**がアセットの SHA-256 ダイジェスト（64 文字の小文字 16 進数、拡張子なし、サブディレクトリなし）です。これにより次の性質が成り立ちます：

- アーカイブ内に同一アセットのコピーを 2 つの名前で保持することができない；
- `audio/<x>` を展開するリーダーはバイト列をハッシュ化して `<x>` と比較するだけで検証でき、ルックアップテーブルを必要としない；
- アセットを別パックへ移してもアイデンティティが保たれる。

メディアタイプとコーデックは拡張子から推測するのではなくマニフェストによって**宣言**されます——拡張子自体が存在しないためです。

## 3. 安定したアイデンティティ

### 3.1 アセット ID

アセットはその正確なバイト列の SHA-256 ダイジェスト（64 文字の小文字 16 進数）であり、これが**アセットを参照する唯一の方法**です。パスでも、ファイル名でも、アセット配列のインデックスでも決してありません。

ダイジェストはデコード済み音声ではなく格納されたバイト列に対して計算されます。再エンコードされたファイルは別のアセットであり、プロトコルは同じふりをせず正直に区別します：ダイジェストは、誰の信用にも頼らずにこのフォーマットが下せる唯一の主張です。

### 3.2 論理トラックキー

論理トラックはユーザーが聴く 1 つのまとまりであり、1 つ以上のアセットから構成されます。そのキーは任意に選ぶのではなく導出されます：

```
trackKey = <小文字の kind> ":" <プライマリアセットのダイジェストの先頭 32 文字（16 進数）>
```

例えば `course:5d41402abc4b2a76b9719d911017c592` です。`kind` はカタログ種別（`course`、`jukebox`、`battle`、`sequence`、`cutscene`、`mission`、`demo`、`sound_effect`、`boot`、`unclassified`）のいずれかです。

これには意図された 2 つの帰結があります：

- 同じプライマリアセットがコーステーマとジュークボックス項目の両方に使われる場合、`kind` がキーの一部であるため**2 つの**トラックになります。統合してしまうと片方がサイレントに失われます。
- トラックキーは改名できません。パックが自身の `kind` およびプライマリダイジェストと一致しないキーを宣言した場合、そのパックは無効です（`TRACK_KEY_INCONSISTENT`）。お知らせひとつで書き換えられる「安定した」キーはアイデンティティではありません。

### 3.3 再生設定は ID を参照する

コンパイル済みグラフ（`music-graphs/`）はダイジェストでアセットを、`(trackKey, markerId)` で cue を参照します。ファイル内の位置、カタログの行番号、キャッシュファイルなどを決して参照しません。したがってグラフは**場所**ではなく**内容**を記述します。

### 3.4 この設計で得られるものと、そのコスト

アイデンティティが内容から導出されるため、次の操作はユーザーが保存したデータを**無効化しません**：

- **パックの再発行。** アートワーク、ルート、追加アウトロ、表示名の修正などを加えた新バージョンのパックでも、変更されていないアセットのダイジェストは変わりません。保存された試聴バージョンはそれらのアセットを引き続き解決でき、ミュージックグラフも引き続きコンパイルできます。
- **別コーデックへの対応。** ビルドが codec 2 のデコードに対応しても、変わるのは**再生できるもの**であって、アセットが**何であるか**ではありません。ID は一切移動せず、再生不能だったトラックが同じ ID のまま再生可能になります。
- **ディスク上でのファイル移動やリネーム。** フォーマット内にパスが一切含まれないためです。

アイデンティティを変化させる唯一の操作は**音声の再エンコード**です。バイト列が変わり、ダイジェストがそれを正直に反映するためです。これはアイデンティティの不具合ではなく、上書きアップグレードとして扱ってはなりません：

- 再エンコードされたアセットは新しいダイジェストを得て、結果として新しいトラックキーを得ます；
- それを運ぶパックは新しいパックバージョンにする必要があり、保存された試聴バージョンが旧アセットを参照している間は旧アセットを削除してはなりません；
- アプリは再エンコード版を同一 ID の置き換えではなく「追加」として提示する必要があります。

したがってインストーラーのルールは次の通りです：**ユーザーが保存したバージョンが参照しているインストール済みアセットを決して削除せず、既存の ID の下でアセット内容を書き換えないこと。** 既存アセットを同じダイジェストのまま異なるバイト列で置き換えようとするインポートは破損パックであり、拒否しなければなりません（チェックサム比較で検出されます）。

## 4. パックが記録すべきこと、ランタイムが導出してはならないこと

アプリには開発用インポート経路向けにファイル名からこれらの事実を導出するコード（`StageFlowDiscovery.prefixOf`、`StageFlowReader.roleOf`）が存在します。そのコードは手動選択したファイルを使えるようにするためのものです。**パックの内容に対して実行してはなりません。** 名前から導出されたロールは推測に過ぎず、一度マニフェストが受理されてしまえば、パック内の推測は明示された事実と区別がつかなくなります。

したがって本リポジトリのパックリーダーには `roleOf` 系のヘルパーが一切ありません：以下の事実はすべてフィールドから直接読み取られ、欠落したフィールドはフォールバックではなくエラーとなります。

| 事実 | パックの記載箇所 | 推測するとどうなるか |
|---|---|---|
| セクションのロール（Pre_Short, Pre, Bridge, Main, Outro） | `tracks[].parts[].role` | `_Fast` を Main 扱いしたり、部分文字列一致で `_Pre_Short` を Pre 扱いする |
| どのエンディングがどれか | `tracks[].parts[].outro` | 先に読み込まれたアウトロファイルだけを残し、別のエンディングが消える |
| cue 位置とその根拠レベル | `markers/<stage>.json`（`provenance` 付き） | マーカーオフセットをゲームがスケジュールした遷移であるかのように見せる |
| ループ範囲 | `assets[].loopStart` / `loopEnd` | ファイル全体をループさせ、イントロが延々と再生される |
| 遷移の同期ポイント | `tracks[].timing` | `Immediate` を選んでおきながら、その結果を「ゲームの遷移」と呼ぶ |
| メインループの繰り返し回数 | `tracks[].timing.mainRepeats` | デフォルトを 1 や 4 にする；どちらも 1 回の再生長を変えてしまう |
| フェード長 | `tracks[].timing.bridgeFade{In,Out}Beats` | 測定されたことのないクロスフェードを勝手に作り出す |
| コースとトラックの対応 | `stages[].tracks` | 翻訳で変わる表示名で一致判定してしまう |

事実が欠落している場合、リーダーは補完せず**該当トラックを拒否します**。上記テーブルのいずれの行にもデフォルト値はなく、そのためフィールドの省略はゼロ扱いではなくバリデーション失敗となります。

## 5. `provenance`（根拠・来歴）は必須フィールド

宣言されたすべてのタイミングには対応する `provenance` レコードが必要です。根拠レコードなしにタイミングを宣言するパックは無効（`TIMING_WITHOUT_PROVENANCE`）であり、`provenance` リストが空のパックも無効（`PROVENANCE_MISSING`）です。

レベル定義。以下の 4 つが v1 における完全な語彙です；5 つ目の追加は拡張ではなくフォーマット変更です。

| レベル | 意味 | 例 |
|---|---|---|
| `MEASURED_L1` | リソース構造上の事実：コンテナ内のフィールド、指定位置にあるマーカーレコード。 | 調査エクスポートに含まれる 174 個の `Full_ToOutroNN` マーカー位置 |
| `MEASURED_L2` | 音声自体を測定して確立された事実。 | デコード波形がリファレンスレンダリングとサンプル単位で一致；BWAV ヘッダから読み取ったループ座標 |
| `CHOSEN_BY_PROJECT` | 代替案を裏付ける証拠がないため本プロジェクトが行った選択。 | `preludeExit = EXIT_CUE`、`mainRepeats = 2` |
| `UNVERIFIED` | 記録されているが裏付けるものがない。UI がそれを表示して未検証と伝えられるよう保持する。 | 意味が確定していないアウトロ名 |

ルール：

1. 未知のレベルはデフォルト値にせず拒否します。このビルドが知らないレベルを主張するパックは、最も弱いレベルとして読み込むのではなく明示的に失敗させなければなりません：さもなければ `L3_VERIFIED` のような主張が「未検証」にロンダリングされ、データとして表示されてしまいます。
2. レコードはその対象（subject）と対象フィールドを明記するため、根拠の主張が値から切り離されて宙に浮くことはありません。タイミングの場合、対象はトラックキー、フィールドは `timing` です。
3. `MEASURED_L1` のマーカー位置は、ゲームが**いつ**遷移を使うかについては何も語りません。パックは cue リストをスケジュールとしてラベル付けしてはなりません。v1 でマーカーファイル自身の `provenance` フィールドが `L1_MARKER_ONLY` であるのはまさにそのためです。
4. **セクションのタイミングは決して「測定済み」とラベル付けしてはなりません。** `preludeExit`、`bridgeEntry`、`outroEntry`、`outroSwitch`、`mainRepeats`、およびブリッジのフェード長はスケジューリングの決定事項です。いつ遷移するかを示すコンテナフィールドも音声測定も存在しないため、レベルが `MEASURED_L1` または `MEASURED_L2` のタイミングレコードは無効です（`TIMING_PROVENANCE_OVERCLAIMS`）。ここは本フォーマットが単に注記するだけでなく主張そのものを拒否する唯一の箇所です：マーカーオフセットはファイルに関する本物の L1 の事実ですが、その権威をタイミングに流用することこそ、本プロジェクトがすでに一度やり直さなければならなかった取り違えそのものだからです。
5. 根拠はデータと共に行動します。UI は値を表示するあらゆる場所で根拠も表示しなければならず、ランタイムも決して破棄してはなりません。レベルなしで表示されたタイミングは事実として読まれてしまうからです。

## 6. カバレッジとコーデック互換性は宣言必須

マニフェストは `coverage` 内で次を宣言します：

- `totalLogicalTracks`：パックが含む論理トラックの総数；
- `playableLogicalTracks`：そのうちパック自身が再生可能と主張する数；
- `codecKinds`：パック内のいずれかのアセットが使用するすべてのコーデック種別。

`playableLogicalTracks` はリーダーではなくパック自身についての言明であり、「パックが全アセットを非ゼロサイズで収録しているトラック数」を意味します。リーダーはアセットリストからこれを再計算し、自身の内容で裏付けられない数値を宣言するパックを拒否します（`PackCoverage.Coverage.declaredCoverageMatches`）。412 本しか載せていないのに 650 トラック再生可能と宣言することはできません。宣言された `codecKinds` リストも同様に検査されます：実際にアセットが使用する種別と一致していなければなりません。1 つでも省略されれば、デコード不能なアセットが誠実そうな数値の陰に隠れてしまうからです。

このビルドが**実際に**何を再生できるかは、リーダーのデコーダ能力に照らして行う別の計算です：

- `PackCoverage` は、パック内のトラックのうちこのビルドがデコードできる数を報告します；
- パック内に存在するがこのビルドでデコードできない各コーデックと、影響を受けるトラック数を列挙します；
- 再生不能なトラックが 1 つでもあれば `isComplete` は `false` になります。

文言ルールは厳格です：**デコード不能なアセットを含むパックに対して、アプリは決して「100 %」と表示してはなりません。** カバレッジ型は意図的にパーセンテージを一切公開せず、切り上げられる余地をなくしています。代わりに件数と 2 つの文を公開します。

ここには 2 つの異なる完全性の事実があり、それらを混同することこそ本節が防ごうとしている誤りです：

| プロパティ | 問い | false になる条件 |
|---|---|---|
| `isPackComplete` | ファイル内部に整合性があり欠けはないか？ | 宣言件数と内容が一致しない、パッケージ内にアセットが欠けている、コースが存在しないトラックを指している |
| `isComplete` | このビルドはファイルに含まれるすべてを再生できるか？ | 理由を問わず再生不能な論理トラックが 1 つでも存在する |

パックは「それ自体は完全だが、全曲再生可能ではない」という状態になり得ますし、UI はその両方を伝えなければなりません：「パックは完全です；このビルドは 650 曲中 412 曲を再生できます」は真実の文ですが、「100 %」は真実ではありません。

---

## 7. `FULL` パックと `DELTA` パック

```json
"kind": "FULL"    // または "DELTA"
```

`FULL` パックは単独で完結するパックです。`DELTA` パックはインストール済みのベースパックを変更するものであり、対象を明記しなければなりません：

```json
"kind": "DELTA",
"basePackId": "org.example.mkw.base",
"basePackVersion": 4
```

ルール：

1. `DELTA` は `basePackId` と `basePackVersion` を**必ず**指定しなければなりません（`DELTA_WITHOUT_BASE`）。バージョン番号だけでは不十分です：2 つの異なるパックのバージョン 4 は同じベースではありません。ベース ID のない差分パックはたまたま入っている別のパックに適用され、2 つの製品の混成物を生んでしまいます。
2. `FULL` パックはベースを指定**してはなりません**（`FULL_WITH_BASE`）。ベースがあると差分扱いとなり、フルパックとしてインポートすればベースが保持していたすべてをサイレントに落としてしまいます。
3. 差分パックは前進しなければなりません：`packVersion > basePackVersion`（`DELTA_NOT_FORWARD`）。
4. ベースが未インストール、別バージョン、または別のパック ID である差分パックのインポートは、**何も書き込む前に拒否**されます。途中まで適用されることは決してありません：ステージングディレクトリは破棄され、インストール済みパックは無傷のまま残ります。
5. 差分パックは変更するメンバーのみを含みます。差分適用後の結果は、ダイジェストをキーとしてベース内容に差分内容を上書きしたものになります。v1 では差分パックはコンテンツを削除できません：何かを削除する必要があるパックは新しい `FULL` として再発行します。
6. 差分パックは凍結されたベースのアンロック対象範囲を変更してはなりません。ベースが凍結されている場合、差分の `unlock` ブロックは完全に同一でなければならず、異なれば拒否されます。対象コース一覧を書き換えられる差分パックがあれば、ユーザーがすでに聴いたコースを追加してカップの条件を骨抜きにできてしまうためです。

## 8. アンロック規約

スペシャルカップの対象コース一覧は、**パック自身が持つ検証済みかつ凍結された論理トラック一覧**から取得され、ユーザーがたまたまインポートしたファイルからは決して取得されません。

```json
"unlock": {
  "frozen": true,
  "stages": ["Coaster", "PeachBeach", "..."]
}
```

- `stages` はカップに必要な凍結済みコースコードのリストです。空であってはならず、すべての要素がパックに記述されたコースであって、そのトラックが実際にパックに含まれていなければなりません（`UNLOCK_SCOPE_EMPTY`、`UNLOCK_STAGE_UNKNOWN`、`UNLOCK_STAGE_INCOMPLETE`）。
- `frozen` はこのパックバージョンにおいて一覧が変更されないことを宣言します。凍結された一覧のみがカップ資格を定義できます。
- `FULL` でないパック、範囲が凍結されていないパック、内容が不完全なパック、またはこのビルドでデコードできないトラックを範囲に含むパックからは、**対象コースが一切得られません**。そのいずれの場合も `PackCoverage.cupEligibleStages` は空集合を返し、`cupBlocker` がその理由を示します。

資格をユーザーのファイルから導出してはならない理由：もしそうすれば、資格が「何をインポートしたか」の性質になってしまいます。1 コースだけインポートして 30 秒聴けば、1 要素集合上で `allCompleted` が真となりカップが開いてしまいます。`CupEligibility` の `set.isNotEmpty()` 節は空集合の罠を塞ぎますが、こちらは塞げません：1 コースだけの集合は空ではないからです。唯一の防御は、ユーザーが編集できずインポートも縮小できないドキュメントからその集合を得ることです。

凍結（frozen）とは文字通り凍結を意味します：その一覧はパックバージョンの属性です。一覧を変更した再発行は新バージョンとなり、旧一覧が一度も満たされていない場合に限りアプリは新一覧を採用できます。差分パックは一切変更できません（セクション 7、ルール 6）。

## 9. インポート：アトミック性と検証

インポートは、置き換え対象を破損させることができてはなりません。

### 9.1 バッファリングせずストリーミングする

パックはアーカイブのセントラルディレクトリを通じて 1 エントリずつ読み込まれます。パック全体や単一アセットを丸ごとメモリに載せるパスはありません：音声アセットは合計数百 MB に達し、アプリはスマートフォン上で動作するためです。各アセットは固定バッファ（64 KiB）を通じてステージングパスへコピーされながら同時にハッシュ計算されます。

### 9.2 アセットごとの検証

すべての音声メンバーについて、インポーターは次を行います：

1. エントリ名が `audio/<digest>` であり、ダイジェストが 64 文字の小文字 16 進数であることを確認する；
2. 読み込む**前に**、宣言された `byteSize` がエントリの非圧縮サイズと一致することを確認する（不一致なら何も書き込まず中断する）；
3. バイト列をストリーミングしながら SHA-256 を計算する；
4. 計算されたダイジェストをメンバー名およびマニフェストの `assets[].digest` と照合する；
5. 展開されたアセット集合がマニフェストのアセットリストと過不足なく一致することを確認する。

いずれかのメンバーがこれらの 1 つでも失敗した場合、インポート全体が中断されます。部分的にしか検証されていないパックはインストールされず、削除されます。

`checksums.json` は音声以外のすべてのメンバー（`manifest.json`、`catalog.json`、グラフ、マーカー、ルート、アートワーク）を `sha256` と `bytes` でカバーします。自分自身はカバーできません；その整合性はアーカイブ自体が壊れていないことに依拠しており、プロトコルは破損検知以上の主張はしません。**v1 に署名はありません**。したがってチェックサムが検知するのは破損であり、改ざんではありません。

### 9.3 ステージングしてからスワップする

```
staging/  <packId>/<packVersion>.tmp/     <- すべてここに書き込まれる
    audio/<sha256> ...
    manifest.json ...
```

1. `<library>/.staging/<random>/` に展開・検証する。以前失敗した試行が中途半端にマージされたまま再開されないよう、ディレクトリ名はランダムにする。
2. 音声を展開する**前に**、まずマニフェストをパースして検証する。構造的に無効なパックには一切コストをかけない。
3. 差分パックの場合、メンバーを書き込む前にベースパックを解決・検証する。ベースが `(basePackId, basePackVersion)` と一致しなければ、何も書き込まず拒否して中断する。
4. 成功したらステージングディレクトリを `fsync` し、その後 `<library>/packs/<packId>/<packVersion>/` へ**アトミックにリネーム**する。同一ファイルシステム内のリネームはアトミックであるため、クラッシュ後も旧ツリーか新ツリーのどちらかのみが存在し、混在状態にはならない。
5. インストール済みパックのポインタ（`installed.json`）を、`LibraryStore` と同じパターンで一時ファイルと `Files.move(..., REPLACE_EXISTING)` により更新する。このポインタがコミットポイントであり、これが移動するまで新しいツリーは未参照で削除可能である。
6. 何らかの失敗が起きた場合はステージングディレクトリを削除し、ポインタを含め既存のインストール済みパックをそのまま残す。ユーザーへ報告するエラーには失敗したアセットまたはメンバー名を明記する。保存された試聴バージョンからまだ参照されている旧パックは、置き換えず保持しなければならない。
7. インストール済みツリーの上へ直接展開してはならず、インポート中に既存アセットを削除してはならない。ガベージコレクションは独立した明示的操作であり、まず保存済みバージョンを参照しなければならない。

## 10. `manifest.json` リファレンス

すべてのキーは大文字・小文字を区別します。未知のキーは無視され、既知のキーに対する未知の**値**は拒否されます（セクション 12）。

### 10.1 トップレベル

| Key | Type | Required | Rule |
|---|---|---|---|
| `formatVersion` | integer | 必須 | `1` でなければならない；それ以外は先を読まずに拒否 |
| `packId` | string | 必須 | `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`；ディレクトリ名になるため区切り文字や `..` を含めてはならない |
| `packVersion` | integer | 必須 | >= 1、`packId` ごとに増加 |
| `name` | string または省略 | 任意 | 人間向けの名前；省略または空白の場合は `packId` にフォールバック |
| `kind` | `"FULL"` または `"DELTA"` | 必須 | それ以外は拒否 |
| `basePackId` | string または null | `DELTA` 時 | `DELTA` では必須、`FULL` では禁止 |
| `basePackVersion` | integer または null | `DELTA` 時 | `DELTA` では必須、`FULL` では禁止、>= 0 |
| `coverage` | object | 必須 | セクション 10.2 |
| `assets` | array | 必須 | セクション 10.3 |
| `tracks` | array | 必須 | セクション 10.4 |
| `stages` | array | 必須（空可） | セクション 10.5 |
| `provenance` | array | 必須 | セクション 10.6 |
| `unlock` | object | 必須 | セクション 10.7 |

### 10.2 `coverage`

| Key | Type | Rule |
|---|---|---|
| `totalLogicalTracks` | integer | >= 0；完全なパックでは `tracks` の要素数と一致しなければならない |
| `playableLogicalTracks` | integer | `0 <= n <= totalLogicalTracks`；総数を超える値はパース時に拒否 |
| `codecKinds` | integer の配列 | いずれかのアセットが使用するすべてのコーデック種別；必須（空パックのみ空になり得るが、空パック自体が無効） |

### 10.3 `assets[]`

| Key | Type | Required | Rule |
|---|---|---|---|
| `digest` | string | 必須 | 64 文字の小文字 16 進数；不正な形式は拒否 |
| `byteSize` | integer | 必須 | 音声では >= 0 かつ > 0；負数およびゼロはバリデーション失敗 |
| `mediaType` | string | 必須 | 非空白；例：`audio/x-bwav` |
| `codecKind` | integer | 必須 | >= 0；BWAV チャンネルコーデック種別に対応、`1` = DSP-ADPCM |
| `sampleRate` | integer | 必須 | > 0 |
| `channels` | integer | 必須 | > 0 |
| `frames` | integer | 必須 | > 0 |
| `loopStart` | integer または null | 任意 | `loopEnd` と対で存在、`0 <= start < end <= frames` |
| `loopEnd` | integer または null | 任意 | 省略時はループしない；0 には決してならない |

ループがない場合は `0` ではなく `null` です。フレーム 0 は実在する位置であり、`0..0` のループは「何もない範囲をループする」という主張になってしまいます。

### 10.4 `tracks[]`

| Key | Type | Required | Rule |
|---|---|---|---|
| `key` | string | 必須 | セクション 3.2 の導出値と一致しなければならない、さもなくば `TRACK_KEY_INCONSISTENT` |
| `kind` | string | 必須 | カタログ種別のいずれか、記載通りの enum 名（例：`COURSE`、`SOUND_EFFECT`） |
| `title` | string または省略 | 任意 | 表示専用；省略または空白時は `key` にフォールバック；照合には決して使わない |
| `primary` | string | 必須 | アセットダイジェスト；このトラック自身の `parts` に含まれていなければならない |
| `isFlow` | boolean | 必須 | トラックのパートが同期ポイントで切り替わる場合 `true` |
| `parts` | array | 必須 | 少なくともプライマリを含む；アセットごとに 1 要素、順序付き |
| `timing` | object または null | flow 時 | `isFlow: true` で必須、それ以外は無視 |

`parts[]`：

| Key | Type | Rule |
|---|---|---|
| `asset` | string | アセットダイジェスト；`assets` に存在しなければならない |
| `role` | string | `PRE_SHORT`、`PRE`、`BRIDGE`、`MAIN`、`OUTRO` |
| `outro` | integer または null | `OUTRO` で必須（`>= 0`）、それ以外の全ロールで禁止；トラック内で一意 |

role と sync-point の語彙は凍結された文字列であり、意図的に Kotlin の識別子名とは切り離されています：Kotlin の enum をリネームしてもプロトコルがサイレントに変わってはならないためです。

`timing`：

| Key | Type | Required | Meaning |
|---|---|---|---|
| `preludeExit` | sync point | 必須 | プレリュードを抜けることが許可される位置 |
| `bridgeEntry` | sync point | 必須 | ブリッジへ入る／Main へ渡すことが許可される位置 |
| `outroEntry` | sync point | 必須 | エンディングをリクエストできる位置 |
| `outroSwitch` | sync point | 必須 | 保留中のエンディングを差し替えられる位置 |
| `mainRepeats` | integer | 必須 | >= 1；エンディングが提示されるまでの Main の周回数 |
| `bridgeFadeOutBeats` | number | 任意、デフォルト 0 | >= 0 |
| `bridgeFadeInBeats` | number | 任意、デフォルト 0 | >= 0 |

同期ポイント：`IMMEDIATE`、`NEXT_BEAT`、`NEXT_BAR`、`NEXT_GRID`、`EXIT_CUE`、`NEXT_CUE`、`NEXT_CUSTOM_CUE`。

同期ポイントの欠落または未知の値は拒否されます。デフォルトを `IMMEDIATE` にすると、このフィールドが記録するために存在している区別そのものが消えてしまいます。

### 10.5 `stages[]`

| Key | Type | Rule |
|---|---|---|
| `code` | string | 非空白、`[A-Za-z0-9_-]{1,64}`、一意 |
| `name` | string または省略 | 表示専用；省略または空白時は `code` にフォールバック |
| `tracks` | string の配列 | 論理トラックキー；すべて `tracks` に存在しなければならない |

1 つのコースが複数のトラックを指定できるのは意図された仕様です：1 コースにコーステーマ、バトルアレンジ、テンポバリエーションを別々の論理トラックとして持たせることができます。

### 10.6 `provenance[]`

| Key | Type | Rule |
|---|---|---|
| `subject` | string | トラックキー、コースコード、または `pack` |
| `field` | string | レコードが対象とするフィールド（例：`timing`） |
| `level` | string | `MEASURED_L1`、`MEASURED_L2`、`CHOSEN_BY_PROJECT`、`UNVERIFIED`；未知の値は拒否 |
| `note` | string または null | 値の由来を説明する任意の人間向けメモ |

### 10.7 `unlock`

| Key | Type | Rule |
|---|---|---|
| `frozen` | boolean | `true` のみがカップ資格を定義できる |
| `stages` | string の配列 | 非空；各要素は `stages` に存在するコースコードでなければならない |

## 11. その他のメンバー

### 11.1 `checksums.json`

```json
{
  "formatVersion": 1,
  "members": [
    { "name": "manifest.json", "sha256": "<64 hex>", "bytes": 4321 },
    { "name": "catalog.json", "sha256": "<64 hex>", "bytes": 98765 }
  ]
}
```

自身以外のすべてのメンバーを網羅します。`name` は有効なメンバー名（セクション 1.2）かつアーカイブ内に存在しなければなりません；存在しないメンバーに対するチェックサムエントリ、またはエントリのないメンバーはバリデーション失敗となります。

### 11.2 `catalog.json`

ライブラリ画面が読み取るカタログ。各エントリは論理トラックキーを参照し、それぞれ**パック側**から見た再生可能性 `playable` を繰り返します（セクション 6）。表示用の参考情報に過ぎません：マニフェストが正であり、リーダーはカタログエントリによってマニフェストに存在しないトラックを導入させてはなりません。

### 11.3 `music-graphs/<trackSlug>.json`

1 トラック分のコンパイル済み再生設定で、アセットダイジェストと `(trackKey, markerId)` の cue を参照します。自身のタイミング設定は一切持ちません：タイミングはマニフェストから供給されるため、同期ポイントの記述箇所は厳密に 1 箇所のみとなります。パックが持たないダイジェストをセグメントが参照するグラフは無効です。

### 11.4 `markers/<stageCode>.json`

1 コース分の cue/marker データで、同梱の `cues.json` エントリの形式を再利用します：

```json
{
  "formatVersion": 1,
  "provenance": "L1_MARKER_ONLY",
  "provenanceNote": "Marker records only. The game's scheduling is not established.",
  "code": "Coaster",
  "name": "Coaster",
  "outroCount": 2,
  "hasBridge": true,
  "hasShortPre": true,
  "hasFast": false,
  "cues": [
    { "name": "Full_ToOutro00", "markerId": 12, "frames": 1234567, "sampleRate": 48000 }
  ]
}
```

ルール：cue は `frames` 順に並べる；位置を持たない cue は 0 に置かず破棄する；未知の `provenance` は拒否する（v1 で定義されているのは `L1_MARKER_ONLY` のみ）；cue リストはスケジュールではなく位置の一覧であり、UI はこれを表示するあらゆる箇所でその旨を明示しなければなりません。

### 11.5 `routes/<routeId>.json`

ルートプリセット。保存済みルートがすでにそうしているのと同じ理由から、コースは表示名やパスではなくコースコードで参照します：名前は変わりますが、ID は変わらないためです。

### 11.6 `artwork/<sha256>.<ext>`

コンテンツアドレス指定の画像。許可される拡張子：`png`、`jpg`、`webp`。ダイジェストは格納されたバイト列に対して計算されます。

## 12. バージョニングと互換性

1. **`formatVersion` はドキュメント全体のバージョンです。** 自身が実装していないバージョンを検出したリーダーはそのパックを拒否します。認識できる部分だけをパースしてはなりません。部分的な読み込みは、欠落した事実を推測へとすり替えた「もっともらしいパック」を作り出してしまうためです。これはライブラリファイルが未知のバージョンを隔離するルールと同じです。
2. `formatVersion: 1` を主張するパックは、ここで定義されていないどのキーにも依存してはなりません。未知のキーは無視されますが（将来のビルドがヒントを追加できるようにするため）、それに**挙動**を依存するパックは v1 リーダーに対して無効であり、より高いバージョンを宣言しなければなりません。
3. 必須キーの追加、意味の変更、または enum 値の変更は新しい `formatVersion` になります。
4. `packVersion` は 1 つの `packId` の**内容**をバージョニングするものであり、スキーマをバージョニングするものではありません。表示名を修正しただけでバイトが変わらない再発行であっても、新しいファイルとして公開される以上は新しい `packVersion` になります。差分パックがそれをベースとして指定できなければならないためです。

## 13. リーダー適合性チェックリスト

リーダーは以下のすべてを満たす場合にのみ適合とみなされます：

- [ ] `manifest.json` がないパッケージ、または有効な UTF-8/JSON でないパッケージを拒否する；
- [ ] 実装していない `formatVersion` を先へ読み進める前に拒否する；
- [ ] 未知の `kind`、未知の根拠レベル、未知のロール、未知の同期ポイント、および未知のトラック種別を拒否する；
- [ ] `parts` や `primary` を含め、あらゆる箇所で不正な形式のアセットダイジェストを拒否する；
- [ ] `playableLogicalTracks > totalLogicalTracks` を拒否する（パース時に、他のどの行を信頼するよりも前に）；
- [ ] 宣言された `totalLogicalTracks`、`playableLogicalTracks`、`codecKinds` を実内容と照合し、宣言値をそのまま表示するのではなく不一致を報告する；
- [ ] 根拠レベルが `MEASURED_L1` または `MEASURED_L2` のタイミングを拒否する；
- [ ] アーカイブ外へ脱出するメンバー名（絶対パス、`..`、バックスラッシュ、未知ディレクトリ、複数の区切り文字）を拒否する；
- [ ] ストリーミングしながら全音声メンバーの名前、宣言サイズ、SHA-256 を検証する；
- [ ] 展開されたアセット集合が宣言されたアセット集合と一致することを検証する；
- [ ] バリデーションを実行し、最初の 1 件だけでなく**すべて**の失敗を報告する；
- [ ] ステージングディレクトリとアトミックリネームを用いてインストールし、失敗時はインストール済みパックに一切触れない；
- [ ] ベースが存在しない、または異なる差分パックを、何も書き込む前に拒否する；
- [ ] パック完全性とライブラリ完全性を別個に公開し、一部しかデコードできないパックに対して 100 % と誤認させるパーセンテージを決して描画しない；
- [ ] 凍結済み・完全・かつ全曲再生可能なパック以外からはアンロック条件を満たさせない。

## 14. バリデーション失敗コード

`PackValidation` は `Failure(code, subject, message)` のリストを報告します。コードは安定しており、メッセージは人間向けです。

| Code | Rule |
|---|---|
| `NO_TRACKS` | パックが論理トラックを 1 つも含んでいない |
| `ASSET_SIZE_NEGATIVE` | アセットが負のバイトサイズを宣言している |
| `ASSET_EMPTY` | 音声アセットが 0 バイトである |
| `DUPLICATE_IDENTITY` | 2 つのアセットが同じダイジェストを共有している、2 つのトラックが同じキーを共有している、または 2 つのコースが同じコードを共有している |
| `TRACK_KEY_INCONSISTENT` | トラックキーが `kind:first32(primary)` になっていない |
| `PRIMARY_NOT_IN_PARTS` | トラックのプライマリアセットが自身の `parts` 内に存在しない |
| `TRACK_ASSET_MISSING` | トラックがアセットリストに含まれないダイジェストを参照している |
| `STAGE_TRACK_MISSING` | コースがパックに含まれないトラックキーを参照している |
| `FLOW_WITHOUT_MAIN` | flow トラックに Main パートがない |
| `NON_FLOW_WITH_MANY_PARTS` | flow でないトラックが複数のパートを持っている |
| `OUTRO_NUMBER_INVALID` | outro パートに番号がない、outro 以外のパートが番号を持っている、または 2 つのパートが同じ番号を共有している |
| `FLOW_TIMING_MISSING` | flow トラックが遷移タイミングを宣言していない |
| `DELTA_WITHOUT_BASE` | 差分パックが `basePackId`/`basePackVersion` を指定していない |
| `FULL_WITH_BASE` | フルパックがベースを指定している |
| `DELTA_NOT_FORWARD` | 差分パックの `packVersion` がベースバージョンより大きくない |
| `PROVENANCE_MISSING` | パックが根拠レコードを 1 つも宣言していない |
| `TIMING_WITHOUT_PROVENANCE` | トラックがタイミングを宣言しているが対応する根拠レコードがない |
| `TIMING_PROVENANCE_OVERCLAIMS` | タイミングが `MEASURED_L1` または `MEASURED_L2` とラベル付けされている；タイミングはスケジューリング判断であるため、`CHOSEN_BY_PROJECT` または `UNVERIFIED` でなければならない |
| `UNLOCK_SCOPE_EMPTY` | アンロック範囲にコースが 1 つも挙げられていない |
| `UNLOCK_STAGE_UNKNOWN` | アンロック範囲がパックで記述されていないコースを指定している |
| `UNLOCK_STAGE_INCOMPLETE` | アンロック対象コースにトラックがない、またはそのトラックがパックに含まれないアセットを参照している |

カップ解放条件におけるカバレッジ上のブロッカーは、`PackCoverage` によって別途報告されます：
`PACK_NOT_FULL`、`NO_UNLOCK_SCOPE`、`SCOPE_NOT_FROZEN`、`SCOPE_STAGE_UNKNOWN`、
`PACK_NOT_COMPLETE`、`UNPLAYABLE_TRACKS`。
